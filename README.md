# 饮品热点雷达

一套面向茶饮与咖啡市场的、可追溯的数据分析与热点判断系统。它不是简单罗列帖子，而是把原始内容归并成事件，再通过统一标签和统计口径，帮助品牌、策略和内容团队判断“本周发生了什么、哪些信号值得继续跟踪、证据在哪里”。

当前正式版本为 **V1.2 / 2026-W30**。公开网页：[查看饮品热点雷达](https://yajunmonk.github.io/beverage-hotspot-radar/)；公开方法与脱敏源码：[GitHub `project-source` 分支](https://github.com/YajunMonk/beverage-hotspot-radar/tree/project-source)。

## 这个产品解决什么问题

- 把品牌官号的重复发帖归并成“去重事件”，避免按帖子数量误判市场动作。
- 用可修改的字段、指标和标签字典，统一产品、联名、品牌事件、品类、原料、IP、促销和热点口径。
- 同时保留品牌、三方、KOC 和编辑热点，但严格分层，避免把不同性质的数据混成一个 KPI。
- 让网页上的每个数字和结论都能回到表格、规则、复核决定和单条原帖。

## 三步核心工作流

| 步骤 | 做什么 | 主要结果 |
|---|---|---|
| 1. [数据抓取](01_数据抓取/README.md) | 登记来源、抓取原帖与互动快照、保存运行记录 | 原始数据与可回读证据；Codex 路径已使用，API 路径预留 |
| 2. [数据清洗与分析](02_数据清洗/README.md) | 标准化、事件去重、标签建议、人工复核、指标计算、结论生成 | 事实表、主数据、复核表、BI 汇总表、分析结论和 Excel 数据中心 |
| 3. [网页呈现](03_网页呈现/README.md) | 读取已确认的 BI 数据集并渲染 | 可筛选网页、事件详情、原文直达和移动端页面 |

```text
原始证据
  → 标准化与事件去重
  → 规则打标 + AI建议
  → 人工/Codex复核
  → 确定性脚本计算指标
  → 分析结论与BI数据集
  → Excel数据中心 + HTML网页
```

## 阅读数据时必须知道的边界

- 9 个品牌是当前登记样本，不代表全行业。
- 三方、KOC 和编辑热点用于发现与体验观察，不进入品牌正式 KPI。
- 当前只有一个完整可比周期，因此环比和趋势功能被禁用。
- 点赞是不同发布后时长下的公开快照，不等同销量、曝光或转化。
- 分享数、内容形式，以及 29 条发现层线索的 `captured_at/run_id` 仍需下一轮补采；这些限制已在质量报告中显性记录。

修改原始来源从第 1 步开始；修改标签或统计口径从第 2 步开始；只修改样式与交互才进入第 3 步。任何版本都必须经过数据、工作簿、页面和公开包四层验收后，才能替换正式入口。
